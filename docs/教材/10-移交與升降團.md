# 移交與升降團（支部人員／旅長用）

> 五分鐘睇完。跟住做就得 —— **規矩**：全宇宙嘅移交（跨支部／轉旅／調區／海轉空）都係同一套四步。
> 你唔需要記住流程細節，只需要記住：**移出嘅一方唔會幫你開戶；接收嘅一方一定要收到個檔先做得。**

## 一、四步（來源 → 目標）

| 步 | 邊個做 | 做咩 | 系統會記落邊 |
|---|---|---|---|
| ① 移出 | 來源團領袖 | 成員 →「移交與升降團 → 移出（來源團）」→ 填移去邊度／原因／生效日 | 旅員 `status=TRANSFERRED_OUT`（tombstone）＋ `transferTo`／`transferDate`；來源團歷史**留唯讀** |
| ② 出套裝 | 來源團領袖 | 撳「移出 ＋ 產生移交套裝」 | 一個 JSON（帶 `transferId` ＋ `sha256`）。**面交或者經私密頻道交**，唔好入公開群組 |
| ③ 接收 | 目標團領袖 | 收到檔 →「接收（目標團）→ 匯入移交套裝」→ 貼 JSON（或揀 `.json` 檔） | 驗 sha256 → 冪等 → 撞號 → 建名冊 `status=pending_hash`（同一個 SCOUT_ID） |
| ④ 開戶 | 目標團領袖 | 用系統開戶流程（邀請連結／setup token）俾佢設密碼 | 首登強制改密碼；密碼 hash 住**目標團**嘅安全位置 |

> ⚠️ 密碼永遠唔會隨套裝走（套裝冇密碼欄）。接收方**一定要自己行開戶流程**。

## 二、接收嘅四道閘（唔會靜靜幫你決定）

1. **sha256 對唔上** → 拒收。個檔改過（哪怕改一個字）或者傳壞咗，要來源團再出一次。
2. **冇 `transferId`** → 拒收。冇冪等鍵＝將來會撞單。
3. **重複匯入** → 拒收（同一個 `transferId` 收過就唔會再建）。呢個係保護你唔會一位成員建兩次。
4. **撞號**（本旅已經有同一個 SCOUT_ID 現役／等開戶）→ **阻住**，叫你人手核對。系統唔會幫你二合一。

## 三、家長點算？（最常問）

| 情況 | 家長帳號 | 你要做嘅事 |
|---|---|---|
| **同一個旅**之內移動（升團／換支部） | **零改動** | 咩都唔使做。子女資料用全球 SCOUT_ID，移到邊都解析得到 |
| **轉旅／調區／海轉空** | 來源旅嘅家長戶轉 `LEFT`（children 留住，唔會刪） | 接收旅用套裝內嘅家長 email 發**一次性邀請連結**，家長撳入去就重開戶 |

移出嗰陣系統會出一段**家長通知文案**（copy 得）＝「你嘅子女已經移交到邊度、你嘅帳號已停用、接收旅會發邀請連結…」。
直接 copy 落 WhatsApp／群組就得，唔使自己作文。

## 四、升團季（批量）

一次過處理一班人：**移交與升降團 → 升團季批量** → 揀由邊個支部升去邊 → 剔成員 → 「產生 bundle」→
一個檔帶晒全部人（每一位一個 `transferId`）。接收方逐個驗（同一套四道閘）。

## 五、安全同私隱

- 套裝有姓名、出生日期、家長聯絡 → 當**個人資料**處理：唔好貼喺公開群組、唔好 email 全體、用完刪檔。
- 移交紀錄（`移交` 分頁）留住係為咗審計：邊個幾時移出／接收。
- 離隊滿 12 個月嘅紀錄會由 PDPO 流程匿名化（見系統 →「PDPO 與私隱」）。

## 六、我而家應該做咩？（快速判斷）

- 有人要升團／轉旅 → 你係**來源團**：撳①移出、②出套裝、交檔。
- 你收到一個 `.json` 套裝 → 你係**目標團**：③匯入（四道閘會自動跑）、④行開戶流程。
- 系統話「撞號」→ **唔好**自己改編號、**唔好**刪原本嗰個；人手核對兩個檔案邊個係真，再搵旅長處理。
- 系統話「sha256 唔對」→ 叫來源團重新出一次套裝（唔好自己改個檔）。

## 七、checklist（接收方）

- [ ] 個檔係面交／私密頻道收（唔係公開群組）。
- [ ] 匯入後見到「名冊 status＝pending_hash」。
- [ ] 已發開戶邀請（或 setup token）俾當事人／家長。
- [ ] 來源團已經將成員標為 `TRANSFERRED_OUT`（你喺套裝／對方系統睇得到）。
- [ ] 轉旅個案：已 copy 家長通知文案 + 發咗邀請連結俾家長。
- [ ] 刪咗手上嗰個套裝檔（唔好留喺 Downloads 一年）。
