# 開戶與批核（自助申請 / 純邀請制）

> BUILD §7：「團員／家長喺成員入口提交（YMIS ＋ 姓名 ＋ 聯絡）→ 該 unit db `accountApps` 待批 → 領袖對名冊核對 → 批 ＝ 開戶或邀請連結，拒 ＝ 記錄原因；**同 YMIS 待批唯一**；領袖可改純邀請制。」

## 兩條路

| 路 | 邊個用 | 流程 |
|---|---|---|
| **自助申請**（預設 `open`） | 團員／家長（成員入口，免登入） | 遞交 → `申請` 表 `pending` → 領袖對名冊核對 → 批／拒 |
| **純邀請制**（`invite-only`） | 想完全控制嘅旅 | 只收旅長／教練員嘅邀請連結（12 字、24 小時、一次性） |

旅長切換：**用戶與身份 → 邀請 → 開戶申請模式**。

## 去重規矩（唔會撞戶）

- 同一 YMIS **未批完之前**只會有一張申請（`同 YMIS 待批唯一`）。
- 已經有戶口嘅 YMIS → 直接唔收（回「已經有戶口」）。
- 財務／進度申報：同支部 ＋ 同期只收一張。
- 通告報名：同通告 ＋ 同名（＋YMIS）只收一次。
- 物資借用：同一人 ＋ 同一件 ＋ 同一日只收一次。

## 批／拒

- **批**：`state:'approved'`；如果係開戶申請 → 即刻回一張**一次性邀請 token**（批 ＝ 開戶或邀請連結）。
- **拒**：**一定要寫原因**（`need_reason`），原因會連同 `decidedBy`／`decidedAt` 一齊留喺表同審計。
- 求救（🆘）唔受純邀請制影響 —— 入唔到嘅人**一定**要有路。

## 我而家應該做咩

- 見到申請但對唔上名冊 → 拒 ＋ 寫清楚原因（例：「名冊冇此人／請聯絡團長」）。
- 想收緊 → 切「純邀請制」；記得已有嘅申請照樣要處理完。
