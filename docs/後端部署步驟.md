# 旅系統後端部署步驟（2026-09-26 · 更新至 P14）

> 對象：**ADMIN**（平台管理員）。全部人手做一次，做完之後再行「驗收清單」。
> 兩層：**旅 SHEET（Google Apps Script）** ＋ **平台（Vercel functions）**。兩邊都係零依賴。
> 開始之前可以先跑 `npm run preflight`（只報變數名同狀態，唔會印值）睇下差啲咩。

---

## 0. 前置（一次性）

| 要咩 | 喺邊 | 攞法 |
|---|---|---|
| 旅 SHEET | 新開一個 Google Sheet（名：`旅_82` 之類） | 直接開，之後 GAS 會自己建 20 個分頁 |
| `Code.gs` | 本 repo `apps-script/Code.gs` | 複製全文 |
| Vercel 專案 | 本 repo 部署（Root＝repo 根） | 已有 `vercel.json`（hkg1） |

---

## 1. 旅側：上 `Code.gs`

1. 開個新 Google Sheet → **擴充功能 → Apps Script**。
2. 刪走預設 `Code.gs` 內容，貼上本 repo `apps-script/Code.gs` 全文 → 儲存。
3. 執行 `initializeSheets()`（授權一次）→ 會建齊分頁（`旅員`／`支部`／`模組開關`／`財務整合`／`物資整合`／`旅通告`／`旅行事曆`／`公開資料`／`分享`／`求救`／`邀請`／`申請`／`移交`／`教材`／`進度摘要`／`備份紀錄`／`設定值`＋`審計紀錄`／`操作紀錄`／`同步紀錄`）。
   - 呢一步同時**自動生成 APIKEY**（`troop_` ＋ 32 hex），只存喺 ScriptProperties，**唔會落 Sheet**。
4. 執行 `seedFirstChief('你嘅email')` → 回一個 **12 字一次性 setup token**（記住佢；等等喺網站兌換成密碼）。
5. **部署 → 新增部署 → 類型「網頁應用程式」**：
   - 執行身分：**我**
   - 存取權：**任何人**
   - 部署完攞 **`/exec` 網址**。
6. Sheet 選單「旅系統」→「🔑 顯示 BACKEND／APIKEY」（會彈窗顯示兩個值）→ 交俾 §2。
   - ⚠️ 呢兩個值**唔可以**入 git、唔可以貼去公開地方。
7. **（P6 忘記密碼／邀請連結要先寄信）** 喺 GAS `專案設定 → 指令碼屬性` 加：
   - `APP_URL` ＝ 你嘅旅系統網址（例 `https://troop-82.vercel.app`）—— 有咗佢，一次性連結先用得；
     未設定或者寄信配額用晒＝系統會**老實回一個「人手傳」token**（唔會扮寄咗）。
8. **（P12 支部接駁）** 每個下游 portal 抄 `apps-script/Downstream.gs`（見 `docs/教材/12-下游接入.md`）；
   佢會用同一個 `API_KEY` 機制，唔使喺旅側改任何嘢。

## 2. 平台側：Vercel env

Settings → Environment Variables（Production）：

| 名 | 值 | 例 |
|---|---|---|
| `TROOP_82_BACKEND` | 上面嘅 `/exec` 網址 | `https://script.google.com/macros/s/AKfy…/exec` |
| `TROOP_82_APIKEY` | 上面嘅 APIKEY | `troop_…` |
| `SESSION_SECRET` | 隨機 32+ 字（session 簽名） | `openssl rand -hex 32` |
| `SUPER_KEY` | 平台超管密鑰（可選，但強烈建議） | 同上 |
| `ADMIN_ISSUE_ENDPOINT` | Scout Admin 收件匣 GAS（可選；唔設就用硬編碼） | `https://script.google.com/macros/s/…/exec` |
| `VAPID_PUBLIC_KEY` | 圖書館推送鏈嘅 VAPID **公鑰**（P14；未設＝訂閱只存本機） | 由館方提供（base64url） |
| `PUSH_INGEST_URL` | 館方訂閱收件位（Supabase Function／webhook） | `https://…supabase.co/functions/v1/push` |
| `PUSH_INGEST_KEY` | 收件位要嘅 Bearer（如需要） | 由館方提供 |

> ⚠️ **VAPID 私鑰永遠唔會喺旅側**：發送權只喺館方（見 `docs/教材/13-個人化訂閱與推送.md`）。

`TROOP_<旅ID>_*` 嘅**旅ID 唔補零**（`TROOP_82_…`；`0082` 都得，兩款都會認）。

Redeploy 一次（env 要重新 build 先生效）。

## 3. 第一次開戶（旅長）

1. 開 `https://<你嘅網域>/?step=unit` → 揀旅 → 身份分流撳「旅長／教練員」→ 應該行到登入頁。
2. 撳「**第一次設密碼**」（setup token 嗰條路）→ 填 email ＋ §1.4 嘅 12 字 token ＋ 新密碼（≥8 字）。
   - 前端會 POST `/api/auth {action:'setupFirstChief'}` → server 用 **PBKDF2-SHA256 100,000** 算 hash → 交 `Code.gs` 寫入 `旅員`。
3. 之後就可以用返 `?step=unit` → 登入（走 `/api/auth`，session 落 HttpOnly cookie）。
4. 旅長入到之後，去「**用戶與身份**」邀請其他人（可揀「順便為下游開戶」＝兩邊同一個 hash）。

## 4. 支部接駁（下游）

1. 旅側「**支部與接駁**」→ 新增下游：支部 ID（例 `vs0082`）、名稱、**下游 `/exec` 網址**、**下游 APIKEY**。
   - 呢啲值只住 `ScriptProperties`（唔會落 Sheet、唔會經 API 出街）。
2. 撳「**測試連線**」→ 回 `ok` 就綠燈。
3. 下游側（例 `vsbadge`）要已經 built：`handleSignedRequest` ＋ `DOWNSTREAM_*` ＋ `ALLOW_LOCAL_LOGIN`。
4. 要閂下游直接登入：撳「**閂閘**」→ 下游寫低 `localLogin:false`（本機 403；出入只經旅入口）。

## 5. 驗收清單（做完逐項打勾）

> 呢張係**唯一判準**：本機測試綠（`npm run check`）≠ 真環境通。

**基本（P0–P5）**
- [ ] `Code.gs` 選單「後端實況 dbInfo」→ 分頁齊、`chain.ok === true`、`properties.apiKey === true`、`shard.ok === true`。
- [ ] 錯 APIKEY 打 `/exec`：`{"success":false,"code":"bad_key"}`。
- [ ] 錯簽名打 `/exec`：`{"success":false,"code":"bad_sig"}`；同一 nonce 第二次：**拒**（重放）。
- [ ] 網站登入：正確密碼入到；錯 5 次 → 鎖 15 分鐘；session 30 分鐘後失效。
- [ ] 未改密碼（`mustChangePw`）嘅人：做嘢 → `403 must_change_pw`。
- [ ] 「儲存到後端」→ 真收據（`confirmed:true`，逐表 `wrote`／`readBack`）。
- [ ] 篡改 `審計紀錄` 一行 → `dbInfo` 嘅 `chain.ok` 變 **false**。
- [ ] 刪最後一個旅長 → **擋**（`keep_one`）。
- [ ] `/api/units?diag=1` → 只列**變數名**（唔會有任何值）。
- [ ] `/api/downstreams?unit=82` → 只有 id／name／api／linked（**冇 URL／KEY**）。
- [ ] 求救 → ADMIN 收件匣真係收到（`type:'issue'`、8 欄）。
**新功能（P6–P14）**
- [ ] **忘記密碼**：登入頁「唔記得密碼？」→ 入自己 email → 收到信（或者旅長收到「人手傳」token）→
      撳連結設新密碼 → 登入成功；**再用同一條連結** → `bad_token`（一次性）。
- [ ] **子女綁定**：家長戶送出一個**名冊上有**嘅 YMIS → 待辦出現；名冊對唔上嘅 → ⚠️ 標示並且批唔到；
      領袖確認之後家長先見到子女；同一張再批 → `decided`（唔可以決定兩次）。
- [ ] **樂觀鎖**：兩個 browser 同時改同一格 → 後改嗰個收到 `conflict`（**唔會覆蓋**），
      系統→同步 自動重讀重合併一次。
- [ ] **讀取樂觀化**：系統 →「同步」嘅「上次讀取覆查」顯示「一致」（唔一致會老實寫「讀取期間有人寫入」）。
- [ ] **sig jti**：同一張簽名 replay 第二次 → `bad_sig`（訊息含「jti／nonce 已用過」），
      而且**清咗 cache 都仍然拒**。
- [ ] **紀錄只記 metadata**：喺 Sheet `審計紀錄` 睇最新一兩行 →
      detail 係狀態／版本／`[內容不記錄 len=N]`，**唔會有通告內文或完整 email**。
- [ ] **移交**（有支部接駁先做）：移出 → 出套裝（sha256）→ 目標團匯入 → 撞號／重複匯入都要拒。
- [ ] **子女／通告面**：待辦各分頁（開戶／子女綁定／財務／移交／求救）逐個撳一次，冇 console error。
- [ ] **推送訂閱**：訂閱頁顯示「推送鏈：已開通」→ 撳「開啟推送」→ 瀏覽器問權限 → 成功之後
      館方 Supabase 見到一筆 `source='troop_portal'`（**冇 email／姓名**）；收一次測試推送 → 撳通知開得返 APP。
- [ ] **下游範本**：揀一個 portal 抄 `Downstream.gs` → 旅側「測試連線」綠燈 → 閂口之後該 portal 本地登入回
      `local_login_closed`（**帶求救指引**），而經旅入口入得。
- [ ] `npm run preflight`：✗ 全部清走（必要 env 齊）。
- [ ] 一句：**紙上／本機測試綠 ≠ 真環境通**；呢張清單係唯一判準。

## 6. 出事點算（fail closed）

| 症狀 | 意思 | 做法 |
|---|---|---|
| `not_configured`（501／503） | Vercel env 未設／未 redeploy | 補 env → redeploy |
| `bad_backend` | BACKEND 唔係 `/exec` | 貼返正確網址 |
| `連唔到旅 SHEET` | GAS 部署權限唔係「任何人」 | 重新部署（執行身分：我；存取權：任何人） |
| `gas_fail` ＋ 訊息 | GAS 內部錯 | 開 Sheet → 「執行紀錄」睇 stack |
| 全部人入唔到 | 可能改壞咗 `旅員` 分頁 | 用 `exportAll` 備份還原；或跑 `seedFirstChief` 重新種一個旅長 |
| APIKEY 外洩 | 有人見到 window／log | 選單「🔄 輪換 APIKEY」→ 更新 Vercel env → redeploy（下游唔受影響） |
| 忘記密碼「寄唔到信」 | GAS `APP_URL` 未設／每日寄信配額用晒 | 設 `APP_URL`；或照系統回嘅「人手傳」token 當面交本人（見教材 11） |
| 推送「未開通」 | `VAPID_PUBLIC_KEY`／`PUSH_INGEST_URL` 未設或未 redeploy | 補 env → redeploy（見教材 13） |
| 分件寫入失敗 | Sheet 太大／權限 | 睇 `操作紀錄` 嘅 `SHARD_ROLLBACK_FAIL`：有＝即刻由 `exportAll` 備份匯入（系統會回滾，但唔保證每次都成） |
| 下游收唔到 sig | purpose 唔同／key 換咗 | 旅側登記嘅 `PURPOSE` 要同下游常數一樣；換 key＝三處同步（見教材 12） |

> 死規矩：**唔會**自動修、**唔會**靜靜當成功。所有失敗都回一個明確 `code`。
