## 0. 一句話

**同一份 `Code.gs` 部署喺每一層（旅／團／進度）；旅系統係「一個 codebase 服務多個旅」嘅管理層站點 ——
所有人由旅呢個窗口入，入到去先揀支部；旅只做管理層（開戶、接駁、權限、聚合、公開資料），
支部嘅數據永遠住喺支部自己張 Sheet，旅要用就經 `sig` 讀返嚟。**

```
                    平台 ADMIN（scout-admin：收件匣、units 登記、SUPER_KEY）        ← 唔屬旅，只登記
                              │  登記 B / C / D + Redeploy
                              ▼
        ┌──────────────────────── 旅系統（本 repo：troop_portal）────────────────────────┐
        │  旅 SHEET ＋ 一支 Apps Script（/exec）＝ 一個 leaf 後端（旅自己都係一個節點）    │
        │  · 旅員（旅長／跨團領袖／家長）  · 下游登記  · 入口掣  · 模組開關  · 公開資料    │
        │  · 財務整合／物資整合（獨立分頁）  · 每支部一頁（跳轉）  · 審計                 │
        │  ScriptProperties：DOWNSTREAM_<id>_{URL,KEY,NAME,AT,PURPOSE}（唯一 registry）  │
        └───────┬─────────────────────────────┬─────────────────────────────┬───────────┘
                │ sig（讀／寫）                │ sig                         │ sig
                ▼                              ▼                             ▼
     團＝支部系統（vs_portal）        團＝支部系統（cubs_portal…）     進度 leaf（vsbadge…）
     團 SHEET ＋ /exec               …                             進度 SHEET ＋ /exec
     ALLOW_LOCAL_LOGIN（上游控・下游寫）                              ALLOW_LOCAL_LOGIN
```

- **旅係上游、團係下游、進度係團嘅子 leaf**：`sig` 鏈單向（旅 → 團 → 進度），下游同步回一個結果，**冇 callback endpoint**（`readme` §4 三條）。
- **接入完全自願**：唔登記下游 = 該團一切照舊；登記咗未閂口 = 一切照舊（旗未設定 = 開啟）。
- **一個人由頭到尾只有一個身份誕生地**（開戶錨點，§3.2），其餘層靠 `sig`／同步落去。

2. **`vs_portal` 未有下游側 sig**：`login`／`apply`／`changePassword` 一律永不接受（`readme` §3.1），`verifyPw` 亦係 VS／RS 未實作項（§12 ⑥）。
   → 旅**唔可能**代成員驗密碼；成員登入路線要明確定案（§3.3）。
3. **`vs_portal` 已經有 portal 入口**（免登入帶身份跳轉，核 `portalOrigin` + `portalRoles`）

## 2. 部署形態：一個 codebase、多個旅

### 2.1 形態（照你定案）

- **一個 repo（本 `troop_portal`）＋ 一個 Vercel project，服務多個旅**（同 `vs_portal`／`vsbadge` 同構）。
- **每個旅一套後端**：旅 SHEET ＋ 一支 Apps Script `/exec`（`Code.gs` 由 `scripts/build-gas.mjs` 生成，單一來源）。
- 註冊兩層（照 `readme` §1）：

| 層 | 放喺邊 | 內容 | 邊個改 |
|---|---|---|---|
| 平台 registry | `data/units.json`（公開 metadata）＋ Vercel env `TROOP_<旅ID>_BACKEND`／`_APIKEY`／`_NAME` | 邊個旅存在、前端看得見嘅名 | ADMIN（scout-admin 收件匣 → Redeploy） |
| 旅 registry（**下游清單**） | **旅 GAS `ScriptProperties`**：`DOWNSTREAM_<id>_URL`／`_KEY`／`_NAME`／`_AT`／**`_PURPOSE`** | 旅之下邊幾個支部／進度被登記 | 旅長（Sheet 選單），**唔郁 Vercel env、唔入任何 Sheet** |

- **`TROOP_OPS` 表：唔建**（跟 `readme` 2026-09-23 定案 —— 「以 Script Properties 為唯一真理，唔好兩份並存」）。
  旅層**營運數據**（旅員、整合、公開資料、模組開關）**唔屬 registry**，住旅 SHEET 分頁（§5）。

### 2.2 旅 ID 與團 ID

- 旅 ID：`normId` 單一實現（`trim → 大寫 → 數字補零至 4 位 + 字母尾`，`readme` §1），例：`0082`。
- 團（支部）ID：**沿用該團自己系統嘅登記編號**（VS 就係 `0082`、cubs 就係佢自己嗰個），因為下游 `/exec` 同 `_KEY` 係跟該團。
- 同一旅之下多個支部（深資／童軍／幼童軍…）**唔係改 ID**，而係**多條 `DOWNSTREAM_<id>`**，`<id>` 由旅長自訂
  （例：`vs0082`、`sc0082`、`cubs0102`；只可用英數／底線／連字號，最長 32）。
  → 前端顯示名用 `DOWNSTREAM_<id>_NAME`（例「82旅 深資童軍團」）。
- **前端顯示用嘅支部清單**（名、支部別、色、可否進入）由旅 GAS 一個讀 action 吐出（`getDownstreams`，**唔含 URL／KEY**）。

### 2.3 變數 ABCD（旅版，四個都唔寫入 SHEET）

| 代號 | 名稱 | 邊個產生 | 放喺邊 | 用途 |
|---|---|---|---|---|
| **A** | `SUPER_KEY` | 現有（隱藏） | Vercel env（旅 project） | 中央登入／超管；**與旅接駁無關，不顯示於任何選單** |
| **B** | `TROOP_<旅ID>_BACKEND` | 部署後抄（`ScriptApp.getService().getUrl()`） | Vercel env；旅自身對下游則係 `DOWNSTREAM_<id>_URL` | 旅前端 proxy 打去邊支 `/exec` |
| **C** | `TROOP_<旅ID>_NAME` | 自填 | Vercel env | 前端旅名顯示（純文字） |
| **D** | `TROOP_<旅ID>_APIKEY` | 旅 GAS 生成（Script Properties `API_KEY`） | Vercel env；旅自身對下游則係 `DOWNSTREAM_<id>_KEY` | apikey，同時係**旅對自己下游簽 `sig` 嘅根密鑰** |

- 一次過抄 B＋D：旅 Sheet 選單「**🔗 旅系統 → 🔑 顯示 BACKEND／APIKEY（交 ADMIN）**」。
- 交 ADMIN：首頁「📋 新旅部署」→ `submitRegistration` → 同源 `/api/proxy` → 伺服器端固定收件匣（`scout-admin`）。
- 換 D＝三處同步：① 旅 Script Properties 刪 `API_KEY` → `showApiKey()` 重生；② 旅長重新登記下游（逐條）；③ ADMIN 改 Vercel env + Redeploy。

## 3. 帳號與登入窗口（旅＝所有人嘅入口）

### 3.1 設計立場

**旅係所有人嘅登入窗口，但唔係所有人嘅身份源頭。**
旅做「窗口」＝ 統一入口、統一導流、統一體驗；身份**邊度誕生就邊度驗**（開戶錨點）。

| 角色 | 帳號住邊（錨點） | 喺旅點登入 | 入到去睇到 |
|---|---|---|---|
| **旅長** | 旅 SHEET（首個由生 GS 種入，§3.4） | 旅登入頁（EMAIL＋PW） | 旅層全部 + 各支部（`branch_access`） |
| **跨團領袖**（教練員、旅層職務） | 旅 SHEET ＋ `branch_access` | 同上 | 旅層 + 被授權支部 |
| **支部領袖**（只帶一團） | 該團支部 SHEET（邀請連結，旅長可經 `sig` 代發） | 旅登入頁 → 揀自己支部 → **轉入該團** | 自己團（團內一切照團嘅權限） |
| **家長** | 旅 SHEET（有旅就旅；`children_ids` 存全球 SCOUT_ID／YMIS） | 旅登入頁（EMAIL＋PW） | 子女**跨支部**資料（§3.6）＋旅公開／通告 |
| **成員**（SCOUT_ID／YMIS） | 該團支部 SHEET | 旅窗口「成員入口」→ 揀自己支部 → **轉入該團成員入口**，由**團**驗密碼（§3.3） | 自己團（成員 App） |

> 一句：**旅窗口睇起上嚟係「一個入口」；技術上「領袖／家長驗喺旅、成員驗喺團」。**

### 3.2 開戶錨點（照 `readme` §2，旅版落實）

```
成員（SCOUT_ID／YMIS）＝ 該團支部 SHEET（名冊所在）
   ├─ 人手／CSV／批核申請／接收移交（全部係該團動作）
   ├─ 旅長想幫某團開成員 → 經 sig 入該團落筆（AUDIT 記 actor=旅長 via=sig）
   └─ ❌ 成員 row 永不入旅 SHEET（成員 App 只打所屬團支部後端）
領袖（EMAIL）＝ 所屬層
   ├─ 只帶一團 → 該團支部（邀請連結；旅長可經 sig 代發）
   ├─ 旅長／跨團 → 旅 SHEET ＋ branch_access
   └─ 每個 leaf 至少留一個本地領袖戶（災難恢復）
家長（EMAIL）＝ 有旅系統 → 旅 SHEET（「同旅移動零改動」先做得到）
進度 leaf ＝ 純下游：唔開成員戶、唔反寫上游（只被 sig 讀寫 + 接受匯入）
```

### 3.3 ★ 旅入口＝支部入口（2026-09-25 用戶定案，改變架構）

```
用戶原話：「旅入口 = 支部入口，理論上我係旅入口選岩自己係咩團就可以入到我支部張 SHEET，
          只係多左 1D 其他支部既野 SHOW 到比我睇（因為佢地 SHARE 左去比我／我支部）」
```

落實：

| 面向 | 舊（本計劃 v1） | 新（定案） |
|---|---|---|
| 定位 | 旅係**導流站**：帶你去該團入口，再登入一次 | 旅入口**就係**你支部嘅入口：入到去已經係**你支部嘅世界** |
| 登入 | 旅驗旅層帳號；支部人員轉去該團入口 | 一個旅閘：旅長／教練員／家長直接用；支部人員**先揀團**再登入 |
| 支部介面 | 由支部系統（vs_portal 等）自己出 | **照樣由支部系統自己出**（唔改；用戶選「支部保留自己介面」）；旅只負責門戶、身份、聚合 |
| 睇得到嘅嘢 | 旅層資料 ＋ 被授權支部 | **你支部嘅嘢** ＋ **其他支部 share 咗、並經你支部接收**嘅嘢 |
| 跨支部 | 旅長／branch_access 授權 | 一樣，但補上：**收件方決定**（見 §3.3b） |

★ 用戶明確要求：**唔想每個旅團都要再改**（唔想逐個團 repo 加嘢）。
所以落實次序係：**旅側先做**（唯一入口、身份、分享、聚合都喺旅）；
團側嘅配合（例如一條 `verifyLogin` 讀 action）列做**可選**，唔做都行得通 ——
唔做就係「旅閘收集帳密 → 經 `sig` 交該團驗」變「旅閘只做門戶：登入仍然喺該團 Sheet 驗正，旅唔存 hash」。

剩低一個要拍板嘅位（唔阻 UI）：帳密喺旅打嘅話，驗密碼嗰步一定要該團做（團側加一條讀 action）；
如果連嗰條都唔想加，就係「旅閘帶你去團入口，你喺嗰度打密碼」—— UI 兩者都支援，用 `ALLOW_LOCAL_LOGIN` 決定。

### 3.3b ★ 分享：收件方決定（2026-09-25 用戶定案）

```
用戶原話：「類似 3. 我係深資決定 SHARE 比童軍，童軍比唔比佢出現就係童軍決定」
```

| 步 | 邊個做 | 做咩 | 系統行為 |
|---|---|---|---|
| 1 發出 | 物主支部（執委 rank ≥ 3） | 揀種類／內容／**目標支部**／可見等級 → 送出 | 寫 `shares[]`，`state: pending`，記 `by`／`at` |
| 2 決定 | **收件支部**（執委或以上／團長；旅長可代，會記 `decidedBy`） | 接收＝**先會出現**；退回＝**留紀錄**（`decideNote` 理由） | 未決定＝**只喺「分享中心 · 待接收」**，唔會混入任何清單 |
| 3 出現 | 系統 | 混入接收方清單，每項標明「來自 XX 團」 | 通告→通告頁；活動→行事曆；物資→物資整合；成果→進度摘要 |
| 4 收回 | 收件支部 或 物主 | 任何時間可收回（`withdrawn`）→ 即刻唔再出現 | 收回唔會刪紀錄 |
| 5 對外 | 旅長 | 要免登入睇得到嘅，另外上報旅長批（等級 0） | 公開頁只放旅長批過嘅 |

- 收件方**唔夠決定權**（團員／隊長 rank < 3）：睇得到「待接收」，可以**加註解**（`suggest`）交團長／執委，
  ★ 加註解**唔等於決定**（`state` 仍然係 `pending`）。
- 分享係**一對一或全旅**：唔會自動彈去所有支部。旅層發全旅（`to: 'all'`）＋等級 0 者可以自動接收。
- ★ **種類只做兩樣**（2026-09-25 用戶定案）：「**通告**」（→ 通告頁）同「**活動**」（→ 行事曆）。
  `kind` 欄留住（`item／progress／album／doc`），但 UI 唔開；之後要加先開閘。
  所以收件方接收之後，只會喺**兩個地方**出現：**通告頁**（一組「來自 XX 團」）同**行事曆**（月份格用斜紋「分享」樣式 ＋ 本月活動表）。

### 3.4 第一個旅長（生 GS 時種入）

- 旅 GAS 首次執行 `initializeSheets()` 時建 **`設定值`** 等全部分頁，並彈「**👑 種入第一個旅長**」精靈：
  EMAIL ＋ 姓名 → 寫入旅 SHEET `旅員`（`status:'pending_hash'`）＋發**一次性 setup token**；
  **密碼由旅系統網站設定**（`/api/auth` action `setupFirstChief` 用 PBKDF2 100k 落 hash）—— GAS 永遠唔經手明文密碼。
- 之後嘅旅長／跨團領袖／家長一律由旅長發**一次性邀請連結**（隨機 12 字、24 小時、用一次即廢）。
- SUPER **只可以觸發重設**，唔可以直接開旅長戶（`readme` §2）。
- （`TROOP_OPS` 唔建，所以 setup 頁落旅 SHEET；呢個係對 `BUILD.md` §2「TROOP_OPS setup 頁」嘅落實方式，要入 §11 對齊清單。）

### 3.5 權限模型（2026-09-25 修訂：冇「旅層領袖」）

```
角色（role）＝帳號住邊張 SHEET —— 決定一切
  旅長(chief)      旅 SHEET    全旅最高權限（每旅一位，可轉移）
  教練員(coach)    旅 SHEET    旅層第二種、亦係最後一種角色；按 branch_access 睇指定支部
  家長(parent)     旅 SHEET    監護人；子女跨支部自動併埋
  支部人員(member) 該團支部SHEET 團長／副團長／成員全部係呢一個角色
  超管(super)      平台        隱藏帳號：開旅、接入、輪換；唔喺任何名單／統計／導航出現
  ★ 冇「旅層領袖」呢個角色（舊版 §3.5 嘅 leader 已刪）。旅層只有旅長同教練員。
```

### 4.3 ★ `sig` 點計（旅版：purpose 可登記）

```
根密鑰    = 下游嘅 SHEET KEY（DOWNSTREAM_<id>_KEY）
sigKey    = hex( HMAC-SHA256( message = "<purpose>", key = D ) )      ← purpose 來自 DOWNSTREAM_<id>_PURPOSE
canonical = action + "\n" + ts(毫秒) + "\n" + nonce + "\n" + hex(SHA-256(rawBody))
sig       = hex( HMAC-SHA256( canonical, sigKey ) )
```

- **雙通道**（GAS 302 轉址會遺失 query）：query `?sig=&sts=&snonce=`（digest 綁完整原始 body）＋ body `{…, sig, sig_ts, sig_nonce}`（digest 綁去掉三個 sig 欄位嘅 body）；下游先驗 query，驗唔到再驗 body；**兩組 nonce 一次過消耗**。
- **防護**：時窗 ±5 分鐘（未來時間戳都拒）／nonce 一次性（`CacheService` 10 分鐘）／body ≤ 900 KB／`sig` 必須 64 位 hex／比較前兩邊先各自 SHA-256（避免短路比較）／**一律 POST，唔收 GET 帶 sig**。
- **點解要 purpose 登記**：`readme` §12 ① 明講「每個 repo 一條 purpose，跨 repo 直連唔支援（已知邊界，唔係 bug）」。
  旅會對**多個唔同 repo** 嘅下游（vsbadge／roverbadge／cubsbadge／scoutbadge／vs_portal…），所以旅**必須**逐條下游知道對方要邊條 purpose。
  - 下游側**零改動**：佢照用自己嘅常數驗簽（`LINK_SIG_PURPOSE`），旅只係「照着抄」。
  - 下游選單新增一句「**🔎 本機 sig 用途字串**」顯示自己嗰條（或由 upstream 登記時人手填）；填錯 = 測試連線即刻報「簽名不符」，唔會靜靜地唔通。
  - 呢個係**唯一**對 `readme` 嘅擴充，要入 §11 對齊清單（建議同時寫入 `進度追蹤旅系統升級版.md` §3）。

### 4.5 ★ 支部系統登入通道（上游決定、下游寫、fail closed）—— 2026-09-25 用戶定案

用戶原話（第二次澄清）：
> 「簡單 D 講就係將後端關左由支部系統登入既通道，就算支部系統登記左見到張 SHEET 都唔比佢入。」
> 「目的都唔係因為咁……純係旅自己決定，佢要兩個都入得都可以。」

**就係一件事**：旅側一個掣 —— **閂唔閂「支部系統自己登入」嗰條通道**。
冇「被關／連旅入口都擋」呢個狀態；亦冇「一定要閂」嘅所謂標準狀態。

| 狀態 | 支部系統自己登入 | 旅入口（`sig`） | 灯 |
|---|---|---|---|
| `open` | 得（回 normal） | 得 | 黃 |
| `sig-only` | **唔得**（403 `upstream_only:true`）—— 就算已登記、經 `sig` 睇到張 SHEET，都唔畀佢入 | 得 | 綠 |

- **兩邊都開都完全得**（有時反而方便）—— 純粹係旅嘅決定。
- 控制面：**只有旅側**（「支部 → 接駁與登記 → 支部系統登入通道」）。支部系統只實作行為，**冇按鈕**。
- 手段：`sig` **write action `setGate`**（`{ action:"setGate", gate:"open"|"sig-only", sig, sig_ts, sig_nonce }`）
  → 下游**自己寫** `ALLOW_LOCAL_LOGIN` → 回 `{ success:true, data:{ localLogin, confirmed:true } }`。
  上游唔會代寫下游嘅 Sheet（照 `readme` 三條規矩）。
- **fail-closed**：下游未登記（紅燈）＝ 掣改唔到，改動回 `ok:false`（唔會扮成功）；讀唔到下游狀態時一律當「閂」。
- 每次改動記 `gateBy`／`gateAt`、寫旅 `AUDIT_LOG`（`via:'sig'`）；下游自己亦寫一次。
- 舊欄位關係：`gate:'open'` ⇔ `ALLOW_LOCAL_LOGIN=true`（`localLogin:true`）；`gate:'sig-only'` ⇔ 未設定／`false`。
  舊資料（只有 `localLogin`）由 `gateOfLink()` 推導，所以升級唔會影響現有旅團。

#### 4.5.1 ★ 求救制（ADMIN 處理）—— 2026-09-25 用戶定案（取代「逃生門」）

### 4.6 回傳三條（照 `readme` §4，一條都唔可以混）

1. **中央登入回打**：GAS 收到 `login` 帶 `super_ticket` → 回打**固定受信端點** `SUPER_VERIFY_URL`（寫死喺 `Code.gs` 一行常數，旅版 = `https://<旅系統網址>/api/super`）→ 驗過先發 token。票據 60 秒、AES-GCM、綁定旅、**一次性防重放**；`SUPER_KEY` 只在 Vercel env，Sheet 永遠收唔到密碼或 hash。
2. **sig 鏈單向**（旅 → 團 → 進度）：下游同步回 `{success, data}`／`{success:false, error}`。**上游必須如實轉述**（例「旅已開戶，但支部寫入失敗」），唔可以靜靜地兩邊唔一致。
3. **旅系統冇 callback endpoint**：下游永不主動回打上游；全倉掃 `callback|postMessage|newTrigger|onEdit` 零命中（有守護測試）。

### 4.7 開戶（閂口後）與搬舊數

- 旅選單「**👤 為下游開戶（揀支部）**」＝ `createAccountForDownstream(id, rawUser, manager)`：
  ① 旅本地開戶 → ② 讀回 `password_hash` → ③ `sig` 打下游 `upsertUser`（兩邊同一 hash，同一個臨時密碼兩邊都啱用；首登仍強制改密碼）。
- 成員戶：**只可以由該團落筆** → 旅長要幫某團開成員 = 旅揀團 → `sig` 打該團 `addMember`／`bulkAddUsers`（AUDIT 記 `actor=旅長 via=sig`）。
- 搬舊數（下游已有資料、後掛上游）：**下游主動**「📤 匯出 JSON（含 hash）」→ Drive（建立後即 `Access.PRIVATE`＋`Permission.NONE`；Drive 失敗寫 Logger）→ 新 sheet「📥 匯入 JSON」逐個 `upsertUser` 直插 hash（64 位 hex、撞號阻擋、`transferId` 冪等、一次 ≤2000 筆、完成顯示「新增 X、更新 Y、失敗 Z」）→ 匯完即刪 Drive 檔 → 核對筆數後先閂口。
- **hash 讀唔到**（讀 action 永不含 hash）→ 所以搬數只可以「下游吐」，唔可以「上游拉」。

### 6.5 整合讀取策略（配額／體積）

- 讀取：**server-side cache 5 分鐘**（同 `TROOP_MODULES` cache 一致）＋「強制刷新」掣；前端唔會逐頁打下游。

## 8. 安全、私隱、交接

- **apikey 只存 server**（env／ScriptProperties），永不回前端、永不入 URL、永不入 QR。
- **越權**：`/api/*` 一律 server-side 授權（簽名 scope＋override）；前端 UI 只係提示，唔係閘。
- **審計**：`AUDIT_LOG` append-only、`prev_hash` 鏈、server-side 寫入、ScriptLock 內 commit；24 個月後 purge。
- **PDPO**：開戶帶「家長同意」欄位＋可複製文案（收集咩／用途／邊個睇到／離隊 12 個月刪）；數據清單一張表；離隊 `TRANSFERRED_OUT`／`LEFT` 12 個月 purge 或匿名化。
- **金鑰輪換**：每季例行 rotate；有管理權者離任即刻 rotate；外洩應變＝停 SIG → 收本地密碼 → 換 apikey → registry 更新 + flush cache → 換 `SESSION_SECRET`／`SUPER_KEY` redeploy → 查審計 → 恢復 SIG。
- **秘密掃描**：`tests/api.mjs` 掃成個 repo（`.js/.mjs/.gs/.json/.md/.html`）搵寫死後門／舊 hash；掃描器本身要有斷言驗佢認得出後門。
- **fail closed**：`SUPER_KEY` 冇設＝超管關閉；`ALLOW_LOCAL_LOGIN` 串錯＝閂口；registry 冇登記＝唔准打。
