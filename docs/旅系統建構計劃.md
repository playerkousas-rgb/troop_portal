> **本檔係旅系統嘅唯一施工規格。** 旅系統 = 整個生態嘅**頂點**（TROOP 層）。

## 0. 一句話

**同一份 `Code.gs` 部署喺每一層（旅／團／進度）；旅系統係「一個 codebase 服務多個旅」嘅管理層站點 ——
所有人由旅呢個窗口入，入到去先揀支部；旅只做管理層（開戶、接駁、權限、聚合、公開資料），
支部嘅數據永遠住喺支部自己張 Sheet，旅要用就經 `sig` 讀返嚟。**

```
                    平台 ADMIN（scout-admin：收件匣、units 登記、SUPER_KEY）        ← 唔屬旅，只登記
                              │  登記 B / C / D + Redeploy
                              ▼
        ┌──────────────────────── 旅系統（本 repo：troop_portal）────────────────────────┐
        │  旅 SHEET ＋ 一支 Apps Script（/exec）＝ 一個 leaf 後端（旅自己都係一個節點）    │
        │  · 旅員（旅長／跨團領袖／家長）  · 下游登記  · 入口掣  · 模組開關  · 公開資料    │
        │  · 財務整合／物資整合（獨立分頁）  · 每支部一頁（跳轉）  · 審計                 │
        │  ScriptProperties：DOWNSTREAM_<id>_{URL,KEY,NAME,AT,PURPOSE}（唯一 registry）  │
        └───────┬─────────────────────────────┬─────────────────────────────┬───────────┘
                │ sig（讀／寫）                │ sig                         │ sig
                ▼                              ▼                             ▼
     團＝支部系統（vs_portal）        團＝支部系統（cubs_portal…）     進度 leaf（vsbadge…）
     團 SHEET ＋ /exec               …                             進度 SHEET ＋ /exec
     ALLOW_LOCAL_LOGIN（上游控・下游寫）                              ALLOW_LOCAL_LOGIN
```

- **旅係上游、團係下游、進度係團嘅子 leaf**：`sig` 鏈單向（旅 → 團 → 進度），下游同步回一個結果，**冇 callback endpoint**（`readme` §4 三條）。
- **接入完全自願**：唔登記下游 = 該團一切照舊；登記咗未閂口 = 一切照舊（旗未設定 = 開啟）。
- **一個人由頭到尾只有一個身份誕生地**（開戶錨點，§3.2），其餘層靠 `sig`／同步落去。

2. **`vs_portal` 未有下游側 sig**：`login`／`apply`／`changePassword` 一律永不接受（`readme` §3.1），`verifyPw` 亦係 VS／RS 未實作項（§12 ⑥）。
   → 旅**唔可能**代成員驗密碼；成員登入路線要明確定案（§3.3）。
3. **`vs_portal` 已經有 portal 入口**（免登入帶身份跳轉，核 `portalOrigin` + `portalRoles`）
   → P0 就有「旅揀支部 → 免登入入去」嘅可用路線，唔使等 sig。

## 2. 部署形態：一個 codebase、多個旅

### 2.1 形態（照你定案）

- **一個 repo（本 `troop_portal`）＋ 一個 Vercel project，服務多個旅**（同 `vs_portal`／`vsbadge` 同構）。
- **每個旅一套後端**：旅 SHEET ＋ 一支 Apps Script `/exec`（`Code.gs` 由 `scripts/build-gas.mjs` 生成，單一來源）。
- 註冊兩層（照 `readme` §1）：

| 層 | 放喺邊 | 內容 | 邊個改 |
|---|---|---|---|
| 平台 registry | `data/units.json`（公開 metadata）＋ Vercel env `TROOP_<旅ID>_BACKEND`／`_APIKEY`／`_NAME` | 邊個旅存在、前端看得見嘅名 | ADMIN（scout-admin 收件匣 → Redeploy） |
| 旅 registry（**下游清單**） | **旅 GAS `ScriptProperties`**：`DOWNSTREAM_<id>_URL`／`_KEY`／`_NAME`／`_AT`／**`_PURPOSE`** | 旅之下邊幾個支部／進度被登記 | 旅長（Sheet 選單），**唔郁 Vercel env、唔入任何 Sheet** |

- **`TROOP_OPS` 表：唔建**（跟 `readme` 2026-09-23 定案 —— 「以 Script Properties 為唯一真理，唔好兩份並存」）。
  旅層**營運數據**（旅員、整合、公開資料、模組開關）**唔屬 registry**，住旅 SHEET 分頁（§5）。

### 2.2 旅 ID 與團 ID

- 旅 ID：`normId` 單一實現（`trim → 大寫 → 數字補零至 4 位 + 字母尾`，`readme` §1），例：`0082`。
- 團（支部）ID：**沿用該團自己系統嘅登記編號**（VS 就係 `0082`、cubs 就係佢自己嗰個），因為下游 `/exec` 同 `_KEY` 係跟該團。
- 同一旅之下多個支部（深資／童軍／幼童軍…）**唔係改 ID**，而係**多條 `DOWNSTREAM_<id>`**，`<id>` 由旅長自訂
  （例：`vs0082`、`sc0082`、`cubs0102`；只可用英數／底線／連字號，最長 32）。
  → 前端顯示名用 `DOWNSTREAM_<id>_NAME`（例「82旅 深資童軍團」）。
- **前端顯示用嘅支部清單**（名、支部別、色、可否進入）由旅 GAS 一個讀 action 吐出（`getDownstreams`，**唔含 URL／KEY**）。

### 2.3 變數 ABCD（旅版，四個都唔寫入 SHEET）

| 代號 | 名稱 | 邊個產生 | 放喺邊 | 用途 |
|---|---|---|---|---|
| **A** | `SUPER_KEY` | 現有（隱藏） | Vercel env（旅 project） | 中央登入／超管；**與旅接駁無關，不顯示於任何選單** |
| **B** | `TROOP_<旅ID>_BACKEND` | 部署後抄（`ScriptApp.getService().getUrl()`） | Vercel env；旅自身對下游則係 `DOWNSTREAM_<id>_URL` | 旅前端 proxy 打去邊支 `/exec` |
| **C** | `TROOP_<旅ID>_NAME` | 自填 | Vercel env | 前端旅名顯示（純文字） |
| **D** | `TROOP_<旅ID>_APIKEY` | 旅 GAS 生成（Script Properties `API_KEY`） | Vercel env；旅自身對下游則係 `DOWNSTREAM_<id>_KEY` | apikey，同時係**旅對自己下游簽 `sig` 嘅根密鑰** |

- 一次過抄 B＋D：旅 Sheet 選單「**🔗 旅系統 → 🔑 顯示 BACKEND／APIKEY（交 ADMIN）**」。
- 交 ADMIN：首頁「📋 新旅部署」→ `submitRegistration` → 同源 `/api/proxy` → 伺服器端固定收件匣（`scout-admin`）。
- 換 D＝三處同步：① 旅 Script Properties 刪 `API_KEY` → `showApiKey()` 重生；② 旅長重新登記下游（逐條）；③ ADMIN 改 Vercel env + Redeploy。

## 3. 帳號與登入窗口（旅＝所有人嘅入口）

### 3.1 設計立場

**旅係所有人嘅登入窗口，但唔係所有人嘅身份源頭。**
旅做「窗口」＝ 統一入口、統一導流、統一體驗；身份**邊度誕生就邊度驗**（開戶錨點）。

| 角色 | 帳號住邊（錨點） | 喺旅點登入 | 入到去睇到 |
|---|---|---|---|
| **旅長** | 旅 SHEET（首個由生 GS 種入，§3.4） | 旅登入頁（EMAIL＋PW） | 旅層全部 + 各支部（`branch_access`） |
| **跨團領袖**（教練員、旅層職務） | 旅 SHEET ＋ `branch_access` | 同上 | 旅層 + 被授權支部 |
| **支部領袖**（只帶一團） | 該團支部 SHEET（邀請連結，旅長可經 `sig` 代發） | 旅登入頁 → 揀自己支部 → **轉入該團** | 自己團（團內一切照團嘅權限） |
| **家長** | 旅 SHEET（有旅就旅；`children_ids` 存全球 SCOUT_ID／YMIS） | 旅登入頁（EMAIL＋PW） | 子女**跨支部**資料（§3.6）＋旅公開／通告 |
| **成員**（SCOUT_ID／YMIS） | 該團支部 SHEET | 旅窗口「成員入口」→ 揀自己支部 → **轉入該團成員入口**，由**團**驗密碼（§3.3） | 自己團（成員 App） |

> 一句：**旅窗口睇起上嚟係「一個入口」；技術上「領袖／家長驗喺旅、成員驗喺團」。**

### 3.2 開戶錨點（照 `readme` §2，旅版落實）

```
成員（SCOUT_ID／YMIS）＝ 該團支部 SHEET（名冊所在）
   ├─ 人手／CSV／批核申請／接收移交（全部係該團動作）
   ├─ 旅長想幫某團開成員 → 經 sig 入該團落筆（AUDIT 記 actor=旅長 via=sig）
   └─ ❌ 成員 row 永不入旅 SHEET（成員 App 只打所屬團支部後端）
領袖（EMAIL）＝ 所屬層
   ├─ 只帶一團 → 該團支部（邀請連結；旅長可經 sig 代發）
   ├─ 旅長／跨團 → 旅 SHEET ＋ branch_access
   └─ 每個 leaf 至少留一個本地領袖戶（災難恢復）
家長（EMAIL）＝ 有旅系統 → 旅 SHEET（「同旅移動零改動」先做得到）
進度 leaf ＝ 純下游：唔開成員戶、唔反寫上游（只被 sig 讀寫 + 接受匯入）
```

### 3.3 成員登入路線（**要你定案 —— 本計劃建議 M3**）

| 路線 | 做法 | 代價 | 風險 |
|---|---|---|---|
| **M3（建議）** | 旅窗口只有一個「成員入口」掣：揀支部 → 轉去該團成員入口（`members.html?u=…`，或 portal 入口 `?from=portal&role=member`），**密碼由該團驗** | 零改動、完全合開戶錨點同「無回調」 | 成員會見到一次跳轉（可做無感：同一瀏覽器記住揀過邊個支部） |
| M1 | 旅直接收 YMIS＋密碼 → 旅經 sig 打該團一個新 action `verifyLogin(sub, pw)` | **要團側（VS 類 repo）加 action**；等於開一個密碼 oracle，要限流＋共用鎖定 | 越界改 VS；oracle 風險；GAS 配額 |
| M2 | 旅收 YMIS＋密碼後，旅自存 mirror hash 驗 | **要鏡像成員 row 落旅 SHEET** | ❌ 直接違反「成員 row 永不入旅 SHEET」＋開戶錨點，唔做 |

> **決定之後**：M3 就寫入 §6 前端路由；M1 就要先同 VS 類 repo 開一張「加 `verifyLogin`」嘅單（屬佢哋範圍，唔喺本計劃內）。

### 3.4 第一個旅長（生 GS 時種入）

- 旅 GAS 首次執行 `initializeSheets()` 時建一個 **`設定` 分頁**（單行 key/value），並彈「**👑 種入第一個旅長**」精靈：
  EMAIL ＋ 臨時密碼（12 字隨機）＋ 姓名 → 直接寫入旅 SHEET `旅員` 表（`mustChangePw=true`），**不經邀請連結**。
- 之後嘅旅長／跨團領袖／家長一律由旅長發**一次性邀請連結**（隨機 12 字、24 小時、用一次即廢）。
- SUPER **只可以觸發重設**，唔可以直接開旅長戶（`readme` §2）。
- （`TROOP_OPS` 唔建，所以 setup 頁落旅 SHEET；呢個係對 `BUILD.md` §2「TROOP_OPS setup 頁」嘅落實方式，要入 §11 對齊清單。）

### 3.5 權限模型

```
旅角色：旅長(chief) ＞ 旅層領袖(leader) ＞ 家長(parent) ＞ 訪客(guest, 免登入)
每項資料可見等級（沿用 VS 嘅 5 級 + 旅加一級 0）：
  0 公眾（免登入都睇到）  ← 旅新增：旅公開資料
  1 其他支部登記用戶      ← 旅嘅存在令呢一級由「對外」收窄到「生態內」
  2 團員  < 3 執委 < 4 領袖 < 5 團長／旅長
    · 低級一定睇得到高級睇得到嘅嘢；一項設 N = 「N 級或以上」先見到
branch_access：旅長一鍵開多團（教練員）；跨團只讀／可寫逐項標明
permissions_override：只有直接上級設定，下級 override ⊆ 上級（封頂），記 updatedBy
```

### 3.6 家長頁（旅新增，VS 冇 —— 因為深資自務自治）

- 家長帳號存旅 SHEET：`{email, name, children: [YMIS/SCOUT_ID…]}`（`children` 用**全球唯一成員編號**，所以「同旅移動零改動」）。
- 家長登入旅 → 「**我的子女**」一頁：
  - 每個子女顯示：所屬支部／團、進度摘要（來自該團進度 leaf）、通告／活動（來自該團支部）、繳費狀態（如該團有提交財務）
  - 旅 server-side 逐個子女**解析屬邊個支部** → 用 `sig` 讀該下游（讀 action 白名單，回應永不含 hash）→ 合併渲染
  - 讀唔到（未接駁／團未開 sig）＝ 顯示「該團未接通」而唔係扮冇資料（honest failure）
- 家長**冇**任何寫入權（除自己帳號資料）；所有代辦由支部做（唔越級）。
- 家長「子女編號」綁定：由**該團領袖確認**（避免亂填認人仔）→ 旅記 `verifiedBy`。

### 3.7 密碼／Session／審計（照 `readme` §2 §8，唔另立一套）

- PBKDF2-SHA256 ≥100k＋per-user salt＋timing-safe compare；hash 只存 server，隨 DB 同步前剝走
- 每帳號 5 次失敗鎖 15 分鐘；`mustChangePw` 期間只放行改密碼
- Session：JWT HttpOnly `Secure; SameSite=Lax`，exp ≤30 分鐘＋silent refresh；`/api/proxy` 驗完 session 先 inject apikey
- `ACCESS_LOG`（LOGIN_OK／FAIL／LOCKOUT／RESET）＋`AUDIT_LOG`（append-only、prev_hash 鏈、24 個月後 purge）
- 三點進入並存：上層 `sig`／leaf 本地密碼（受 `ALLOW_LOCAL_LOGIN` 控）／SUPER

## 4. 上下游接駁（`sig`）

### 4.1 拓撲

```
旅 GAS ──sig──▶ 團 GAS（支部系統） ──sig──▶ 進度 GAS
  │                   │                        │
  │ 登記下游：         │ 登記下游：              │ ALLOW_LOCAL_LOGIN
  │ DOWNSTREAM_<id>_*  │ DOWNSTREAM_<id>_*       │ （直接入口掣）
  ▼                   ▼                        ▼
旅 SHEET            團 SHEET                  進度 SHEET
```

**每層都係同一份 `Code.gs`**：一個節點同時可以係上游（對自己下游）同下游（對自己上游）。
旅嘅 `Code.gs` 由本 repo `scripts/build-gas.mjs` 生成（單一來源，唔 commit 生成物當原始碼）。

### 4.2 下游登記（`ScriptProperties`，旅長選單）

| key | 內容 | 註 |
|---|---|---|
| `DOWNSTREAM_<id>_URL` | 下游 `/exec`（**必須** `https://script.google.com/macros/s/…/exec`，其他一律拒） | 旅長自訂 `<id>` |
| `DOWNSTREAM_<id>_KEY` | 下游嘅 SHEET KEY（D）＝ 旅簽出站用嘅根密鑰 | 只存 server，永不落前端 |
| `DOWNSTREAM_<id>_NAME` | 顯示名（例「82旅 童軍團」） | 前端只讀呢個 |
| `DOWNSTREAM_<id>_AT` | 登記時間 | 審計用 |
| **`DOWNSTREAM_<id>_PURPOSE`** | **下游嘅 sig 用途字串**（例 `vsbadge-troop-sig-v1`／`vsportal-troop-sig-v1`） | ★ 本計劃新增，見 §4.3 |

- 選單：**➕ 登記下游（URL＋KEY＋NAME）**、**📡 測試下游連線（sig）**、**✏️ 改顯示名／改 purpose**、**🗑 移除下游**、**🚪 下游直接入口（閂口／開啟）**、**👤 為下游開戶**、**📤 匯出 JSON（含 hash）**／**📥 匯入 JSON**。
- 登記／移除**只改 ScriptProperties**：唔郁 Vercel env、唔入任何 Sheet、唔使 ADMIN 動作（`readme` §1「接入 registry 追加唔搬」）。

### 4.3 ★ `sig` 點計（旅版：purpose 可登記）

```
根密鑰    = 下游嘅 SHEET KEY（DOWNSTREAM_<id>_KEY）
sigKey    = hex( HMAC-SHA256( message = "<purpose>", key = D ) )      ← purpose 來自 DOWNSTREAM_<id>_PURPOSE
canonical = action + "\n" + ts(毫秒) + "\n" + nonce + "\n" + hex(SHA-256(rawBody))
sig       = hex( HMAC-SHA256( canonical, sigKey ) )
```

- **雙通道**（GAS 302 轉址會遺失 query）：query `?sig=&sts=&snonce=`（digest 綁完整原始 body）＋ body `{…, sig, sig_ts, sig_nonce}`（digest 綁去掉三個 sig 欄位嘅 body）；下游先驗 query，驗唔到再驗 body；**兩組 nonce 一次過消耗**。
- **防護**：時窗 ±5 分鐘（未來時間戳都拒）／nonce 一次性（`CacheService` 10 分鐘）／body ≤ 900 KB／`sig` 必須 64 位 hex／比較前兩邊先各自 SHA-256（避免短路比較）／**一律 POST，唔收 GET 帶 sig**。
- **點解要 purpose 登記**：`readme` §12 ① 明講「每個 repo 一條 purpose，跨 repo 直連唔支援（已知邊界，唔係 bug）」。
  旅會對**多個唔同 repo** 嘅下游（vsbadge／roverbadge／cubsbadge／scoutbadge／vs_portal…），所以旅**必須**逐條下游知道對方要邊條 purpose。
  - 下游側**零改動**：佢照用自己嘅常數驗簽（`LINK_SIG_PURPOSE`），旅只係「照着抄」。
  - 下游選單新增一句「**🔎 本機 sig 用途字串**」顯示自己嗰條（或由 upstream 登記時人手填）；填錯 = 測試連線即刻報「簽名不符」，唔會靜靜地唔通。
  - 呢個係**唯一**對 `readme` 嘅擴充，要入 §11 對齊清單（建議同時寫入 `進度追蹤旅系統升級版.md` §3）。

### 4.4 action 白名單（旅 ≤ 團／進度）

- **讀**（上游可讀下游）：`load`、`getLoginMode`、`getLinkState`、`getSummary`、`getMembers`、`getConfig`、`getAllUsers`、`getNotices`、`getFinance`、`getInventory`、`getCalendar`、`getPublicProfile`、`getApplications`、`getAuditLog`
  → 回應**永不含** `password_hash`／`apiKey`／`/exec`（有守護測試）
- **寫**（上游可寫下游）：`save`、`saveTable`、`upsertUser`、`importUsers`、`addMember`、`bulkAddUsers`、`resetPassword`、`updateUserProfile`、`setUserStatus`、`deleteUser`、`updateUserRole`、`updatePermissions`、`saveNotice`、`saveFinanceEntry`、`setLocalLogin`
- **永不接受（即使有 sig）**：`login`、`apply`、`logout`、`changePassword`、`updateConfig`、`requestLogRecord`、`cancelLogRequest`，以及白名單以外任何 action
- 每筆**簽名寫入**喺下游「操作紀錄」留一行（操作者 `upstream`，詳情含 `on_behalf`）；標籤先消毒（只留 `0-9A-Za-z_.@-`）防儲存格算式注入；**讀取唔留**
- 支支部側嘅實際 action 名各自實測（`readme` §12 ②）→ 旅登記下游時**同時登記該下游嘅 action set 版本**（`DOWNSTREAM_<id>_API`，例 `v1`），前端據此決定叫邊個 action，唔會盲撞。

### 4.5 入口掣 `ALLOW_LOCAL_LOGIN`（上游控、下游寫、fail closed）

| 掣值 | 行為 |
|---|---|
| 未設定（預設） | **開啟** —— 現有旅團零影響；`initializeSheets()` 唔會自動寫值 |
| `1`／`true`／`yes`／`on`／`open`（大小寫／空白不敏感） | 開啟 |
| **其餘任何值**（含串錯） | **閂口**（只收 `sig`，本地入口回 403 + `upstream_only:true`） |

- 閂口後：前端直接 `login`／`apply`／`load`／舊 apikey `save`／用戶 token 操作**一律拒**；上游 `sig` 請求同中央登入**照收**。
- 閂口前必須有「經上游用 `sig` 轉發」嘅前端路徑（`readme` 自檢清單）→ 旅嘅 P0 就要有「代支部轉發」呢條路，否則唔准入閂口。
- **每個下游至少留一個本地領袖戶 + SUPER 作災難恢復。**

### 4.6 回傳三條（照 `readme` §4，一條都唔可以混）

1. **中央登入回打**：GAS 收到 `login` 帶 `super_ticket` → 回打**固定受信端點** `SUPER_VERIFY_URL`（寫死喺 `Code.gs` 一行常數，旅版 = `https://<旅系統網址>/api/super`）→ 驗過先發 token。票據 60 秒、AES-GCM、綁定旅、**一次性防重放**；`SUPER_KEY` 只在 Vercel env，Sheet 永遠收唔到密碼或 hash。
2. **sig 鏈單向**（旅 → 團 → 進度）：下游同步回 `{success, data}`／`{success:false, error}`。**上游必須如實轉述**（例「旅已開戶，但支部寫入失敗」），唔可以靜靜地兩邊唔一致。
3. **旅系統冇 callback endpoint**：下游永不主動回打上游；全倉掃 `callback|postMessage|newTrigger|onEdit` 零命中（有守護測試）。

### 4.7 開戶（閂口後）與搬舊數

- 旅選單「**👤 為下游開戶（揀支部）**」＝ `createAccountForDownstream(id, rawUser, manager)`：
  ① 旅本地開戶 → ② 讀回 `password_hash` → ③ `sig` 打下游 `upsertUser`（兩邊同一 hash，同一個臨時密碼兩邊都啱用；首登仍強制改密碼）。
- 成員戶：**只可以由該團落筆** → 旅長要幫某團開成員 = 旅揀團 → `sig` 打該團 `addMember`／`bulkAddUsers`（AUDIT 記 `actor=旅長 via=sig`）。
- 搬舊數（下游已有資料、後掛上游）：**下游主動**「📤 匯出 JSON（含 hash）」→ Drive（建立後即 `Access.PRIVATE`＋`Permission.NONE`；Drive 失敗寫 Logger）→ 新 sheet「📥 匯入 JSON」逐個 `upsertUser` 直插 hash（64 位 hex、撞號阻擋、`transferId` 冪等、一次 ≤2000 筆、完成顯示「新增 X、更新 Y、失敗 Z」）→ 匯完即刪 Drive 檔 → 核對筆數後先閂口。
- **hash 讀唔到**（讀 action 永不含 hash）→ 所以搬數只可以「下游吐」，唔可以「上游拉」。

### 6.5 整合讀取策略（配額／體積）

- 讀取：**server-side cache 5 分鐘**（同 `TROOP_MODULES` cache 一致）＋「強制刷新」掣；前端唔會逐頁打下游。
- 逐個下游一次過攞**摘要**（唔係成份 db）；單次回應守住 Vercel 4.5 MB 上限（`/api/proxy` 自己限 4 MB）。
- GAS 側：每支 `/exec` 每日 URL Fetch 配額（免費 20,000）—— 以「日更摘要＋用戶撳先拉」為準，唔做輪詢。
- 大庫分件（`saveDbPart`／`loadDbPart`／`loadTablesPart`）照抄，唔另創。

### 6.6 旅 `Code.gs` 節（由 `build-gas.mjs` 生成）

1. 選單 `旅系統`：🔑 顯示 BACKEND／APIKEY｜➕ 登記下游｜📡 測試連線｜🚪 下游直接入口｜👤 為下游開戶｜📤 匯出 JSON（含 hash）｜📥 匯入 JSON｜🔎 本機 sig 用途字串｜🧪 後端實況
2. `initializeSheets()`（只建新表，唔清資料）＋ 首個旅長種入（§3.4）
3. `doGet`／`doPost`：`requireAuth` 首行 → 白名單 action → ScriptLock `waitLock(20s)` → 逐表寫 → 自證 → 回 `{success, confirmed, reports}`
4. 下游側：`getLinkState`／`setLocalLogin`／`handleSignedRequest`（驗兩組 sig／nonce 一次性）／`upsertUser`／`importUsers`／`exportUsersJson`
5. `login` 分支：帶 `super_ticket` → `UrlFetchApp` 回打 `SUPER_VERIFY_URL`（§4.6 ①）
6. 診斷：`status`／`dbInfo`／`diag`（分頁行數、壞表、`backendVersion`、`mode=simple|blob|empty`）——**如實報，唔報喜唔報憂**
7. **冇** `onEdit`／`newTrigger`／`postMessage`（無回調，守護測試掃）

## 8. 安全、私隱、交接

- **apikey 只存 server**（env／ScriptProperties），永不回前端、永不入 URL、永不入 QR。
- **越權**：`/api/*` 一律 server-side 授權（簽名 scope＋override）；前端 UI 只係提示，唔係閘。
- **審計**：`AUDIT_LOG` append-only、`prev_hash` 鏈、server-side 寫入、ScriptLock 內 commit；24 個月後 purge。
- **PDPO**：開戶帶「家長同意」欄位＋可複製文案（收集咩／用途／邊個睇到／離隊 12 個月刪）；數據清單一張表；離隊 `TRANSFERRED_OUT`／`LEFT` 12 個月 purge 或匿名化。
- **金鑰輪換**：每季例行 rotate；有管理權者離任即刻 rotate；外洩應變＝停 SIG → 收本地密碼 → 換 apikey → registry 更新 + flush cache → 換 `SESSION_SECRET`／`SUPER_KEY` redeploy → 查審計 → 恢復 SIG。
- **秘密掃描**：`tests/api.mjs` 掃成個 repo（`.js/.mjs/.gs/.json/.md/.html`）搵寫死後門／舊 hash；掃描器本身要有斷言驗佢認得出後門。
- **fail closed**：`SUPER_KEY` 冇設＝超管關閉；`ALLOW_LOCAL_LOGIN` 串錯＝閂口；registry 冇登記＝唔准打。

## 9. 體積治理與工程規矩（唔可以爆 Vercel）

- `api` 零依賴（原生 `fetch`＋`crypto`）；建構工具一律 `devDependencies`；`vercel.json` 用 `npm ci --omit=dev`。
- `.vercelignore`：擋 `node_modules`／`.git`／`.vercel`／`.cache`／`*.bak|tmp|old|log`／`uploads/`／`__tests__/`／`coverage/`／`docs/`／`tests/`／`apps-script/`（生成物）——**只上傳最終靜態產物**。
- 千祈唔好 exclude（運行時必要）：`*.html`、`assets/**`、`data/**`、`api/**`、`scripts/**`、`package.json`／`package-lock.json`／`vercel.json`。
- 圖轉 `AVIF`／`WebP`、單檔 <500 KB；`dist < 5MB`、`bundle < 2MB`（CI 硬攔）；`public/` 死重檔案全文 grep 後刪。
- Vercel Dashboard 關非 `main` 分支 Preview、Retention 7 天；上載面單檔 ≤5 MB、每筆 3 張、每 unit 每日總量上限。
- **版號只留 MD**：`Code.gs` 內唔寫 `// vX.X`（守護測試掃）；版號集中在 `assets/js/lib/version.js` ＋ 本計劃。
- 生成物唔 commit（`apps-script/Code.gs` 由 `scripts/build-gas.mjs` 產生）；APP 內「下載 Code.gs」即時生成。

## 10. 驗收（P0 落碼後要綠）

**旅專屬守護測試**（照 `vsbadge/tests/troop_link.test.mjs` 十項為底，加旅層）：

1. 掣未設定＝行為零變化；閂口後直接登入／申請／load／舊 apikey save 全拒
2. 登記後 `sig` 可讀可寫；上游可閂下游掣；非 GAS URL 拒收
3. `sig` 防護：錯 key／竄改／過期／未來 ts／重放／混合傳送／白名單外 action 全拒
4. ABCD ＋ `DOWNSTREAM_*` **唔落任何工作表**（掃晒 Sheet）
5. 為下游開戶＝兩邊同一 hash、冪等、冇帶 hash 保留原密碼；成員戶只可以由該團落筆
6. 匯出／匯入保留舊密碼；明文密碼／假 hash／壞 JSON 一律拒
7. `getAllUsers` 等讀 action **唔洩 hash／apikey／exec**
8. 上游客戶標籤唔會變儲存格算式（消毒）
9. **`Code.gs` 內冇版號註解**；全倉掃 `callback|postMessage|newTrigger|onEdit` 零命中
10. 旅層：家長子女跨支部合併（讀唔到要老實報）；可見等級 0–5 逐級過濾；公開頁唔含名冊
11. 逐表寫入自證：`confirmed:false` ＝ 當失敗、改動留本機；壞一個表唔影響其他表
12. 中央登入：票據 60 秒、一次性、綁旅；`SUPER_KEY` 冇設＝關閉

**每輪上線前**：`npm run check`（lint → build → test）全綠；真機跑一次（`sig` 過 302 轉址、Drive 權限、ScriptProperties 配額、`onOpen` 選單授權）。
